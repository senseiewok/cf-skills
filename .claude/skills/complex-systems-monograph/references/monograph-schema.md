# Living Executable Monograph Schema & Specification

This specification defines the structural, editorial, mathematical, and accessibility requirements for **Living Executable Monographs** and their **Portable AI-Agnostic `SKILL.md` Companions**.

Research, not medical advice. Structuring a scientific, architectural, or mathematical system into an interactive monograph says nothing about clinical efficacy, patient diagnosis, or medical care.

---

## 1. Document Architecture: The 4-Act Narrative Structure

Every Living Executable Monograph must be structured into four sequential, pedagogical acts:

| Act | Canonical Title | Required Content & Pedagogical Purpose |
| :--- | :--- | :--- |
| **Act I** | **Historical Grounding & Discovery Milestones** | Establishes the human story, historical context, and 4 chronological milestone breakthroughs that led to the modern governing formulation. Grounded in primary sources with explicit publication years. |
| **Act II** | **Governing Equations & Interactive Parameter Scrubbing** | Presents the mathematical formulation with exact dimensional units. Primary parameters must be presented as scrubbable tokens or sliders so the reader can build physical intuition by manipulating inputs directly. |
| **Act III** | **The Multi-Lens Scientific Observatory** | Multi-modal exploration across at least two complementary analytical representations: 2D/3D continuum potential surfaces, phase-space vector fields, Noether-Kirchhoff alluvial conservation ribbons, or polar performance envelopes. |
| **Act IV** | **Dual-Horizon Frontier Discovery & Smart Citations** | Connects the foundational principles to contemporary (2024-2026) scientific and computational frontiers. Every external claim must link to a persistent identifier (DOI, PMID, NCT ID, or Lean 4 formal proof repository) with verified citation context. |

## 2. Living Dated Edition (`REV X.Y`) & Frontier Council Schema

Unlike static print papers, Living Executable Monographs are living documents that evolve alongside formal verification and experimental discovery.

### Required Header Metadata
Each monograph document must declare:
- `title`: Primary scientific title.
- `edition`: Current revision string formatted as `REV X.Y` (e.g., `REV 1.0`, `REV 1.2`).
- `date_published`: ISO 8601 initial publication date (`YYYY-MM-DD`).
- `date_redated`: ISO 8601 latest revision date (`YYYY-MM-DD`).
- `pillar`: Disciplinary track (`engineering`, `architecture`, `physics`, `math`, `biomedical`).

### 4-Seat Multi-Lineage Council Ledger
Every revision requires multi-perspective adversarial review across independent frontier model lineages and deterministic proof kernels:
1. **Seat 1 (Claude Opus lineage)**: Architectural coherence, prose dignity, and conceptual continuity.
2. **Seat 2 (Gemini Argon lineage)**: Mathematical precision, dimensional consistency, and code-level verification.
3. **Seat 3 (GPT-OSS lineage)**: Edge cases, counterfactual stability, and adversarial falsification.
4. **Seat 4 (Deterministic Verification Kernel)**: Offline, zero-network mathematical or structural check (e.g., Buckingham Pi dimensional rank, complex-step derivative agreement, or Lean 4 acyclic proof DAG).

## 3. Portable AI-Agnostic `SKILL.md` Companion Specification

Every monograph provides a 1-click downloadable `SKILL.md` companion allowing researchers and clinicians to load the monograph's verified mental model into any AI agent (Claude Code, GitHub Copilot, Cursor, Google Antigravity, OpenAI Codex, or local Ollama models).

### Companion Requirements
1. **Agent Skills Frontmatter**: Must include `name`, `description`, `license`, and `metadata` (`audience`, `level`, `category`).
2. **Governing Laws**: Explicit mathematical formulation and physical conservation rules.
3. **Offline Verification Oracle**: A Python standard-library runnable snippet that verifies the core equations and rejects poisoned counterfactual inputs.
4. **Scope Boundaries**: Explicit statement of what the skill establishes and what it does not (e.g., mathematical consistency is not clinical efficacy).

## 4. Web Performance & Accessibility Standards

1. **Zero-Build Architecture**: Standard semantic HTML5, CSS Grid with native cascade layers (`@layer`), and native ES6 modules. No npm build step required to view or run.
2. **Zero Cumulative Layout Shift (`CLS = 0.000`)**: All interactive plates, canvas elements, and advertising/patronage slots must have explicit CSS aspect-ratio or fixed min-height reservations.
3. **High-Contrast Typography**: WCAG 2.2 AAA text contrast ratio ($\ge 7:1$ for body prose, $\ge 4.5:1$ for large headings).
4. **Reduced Motion Support**: Honor `@media (prefers-reduced-motion: reduce)` by disabling auto-rotations and looping SVG animations.
5. **DOM Security**: Zero use of `.innerHTML` or `document.write()`; all dynamic DOM manipulation must use `createElementNS`, `textContent`, and safe DOM APIs.
